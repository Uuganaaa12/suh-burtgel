# Definition of Done (DoD)

Төсөл: СӨХ-ийн сууц, машин, зогсоолын бүртгэлийн систем\
Баг: Д.Ууганбаяр (Product Owner), Ц.Номунзаяа (Scrum Master)

Backlog-ийн нэг ажил (User Story эсвэл лабын даалгавар) доорх **бүх** нөхцөлийг хангасан үед л Kanban самбар дээр **Done** баганад шилжинэ. Нэг нөхцөл дутуу бол ажил In Progress хэвээр үлдэнэ.

Энэ жагсаалт нь Лаб 6–12-т бодитоор мөрдөж ирсэн дүрмүүдийг нэг дор бичсэн хувилбар юм.

## Нөхцөлүүд

| № | Нөхцөл | Хэрхэн шалгах | Хаанаас эхэлсэн |
|---|---|---|---|
| 1 | User Story-ийн тайлбар болон холбогдох юзкейсийн үндсэн урсгал ажиллана | Story-ийн «Монгол тайлбар», [design.md](design.md)-ийн юзкейстэй тулгана | Лаб 2 |
| 2 | Код `main` дээр шууд биш, тусдаа branch дээр хийгдэж Pull Request-ээр орно | PR-ийн жагсаалт | Лаб 6 |
| 3 | CI ногоон: pylint 10.00/10, pip-audit эмзэг байдалгүй, pytest бүгд тэнцсэн | PR дээрх GitHub Actions-ийн тэмдэг | Лаб 7, 10, 11 |
| 4 | Шинэ логикт Arrange-Act-Assert бүтэцтэй unit тест бичигдсэн, хэвийн ба хилийн тохиолдлыг хамарна | `tests/` хавтас | Лаб 10 |
| 5 | Багийн нөгөө гишүүн PR-ийг review хийж **Approve** дарсан | PR-ийн «Approved» тэмдэг | Лаб 6 |
| 6 | AI-аар бичүүлсэн код байвал review хийж, тестээр баталгаажуулж, тайланд ил тод тэмдэглэсэн | `docs/` дахь тайлан | Лаб 12 |
| 7 | Холбогдох баримт бичиг шинэчлэгдсэн (README, `docs/labN.md`, backlog-ийн Status) | PR-ийн өөрчлөгдсөн файлууд | Лаб 1 |
| 8 | `main` руу merge хийгдэж, merge-ийн дараах CI ногоон | `main` branch-ийн Actions | Лаб 7 |

## Яагаад эдгээр нөхцөл

- **Тест болон CI (3, 4, 8):**
  - Хүн гараар шалгавал мартах, алгасах эрсдэлтэй.
  - Push бүрт автомат шалгалт ажиллахаар алдаатай код `main` руу орохгүй.
  - Жишээ нь Лаб 10-ын PR #8 санаатай алдаатай байсан тул CI улаан болж, merge хийгдээгүй.
- **Review (5, 6):** Лаб 12-т AI-ийн кодыг review хийх явцад өөрсдийн аппын улсын дугаарын шалгалтад `\d` алдаа байсныг илрүүлсэн. Хоёр дахь хүний нүд тестэд ороогүй алдааг олдог.
- **Баримт бичиг (7):** Багш болон багийн гишүүд repo-оос л ажлын явцыг хардаг. Баримт бичиг кодтой зэрэг шинэчлэгдэхгүй бол хоцорно.

## Харьцуулалт

| | Definition of Done | Хүлээн авах шалгуур (acceptance criteria) |
|---|---|---|
| Хамрах хүрээ | Бүх ажилд нэг ижил | Story бүрт өөр |
| Юуг шалгах | Чанар, процесс (тест, review, CI) | Функц (хэрэглэгч юу хийж чадах) |
| Жишээ | «CI ногоон, Approve авсан» | «Оршин суугч дарааллын дугаараа харна» (US-07) |

Одоогийн backlog-д хүлээн авах шалгуурын тусдаа багана байхгүй. Story-ийн «Монгол тайлбар» болон юзкейс тэр үүргийг гүйцэтгэж байна (1-р нөхцөл). Дараагийн sprint-д story бүрт хүлээн авах шалгуур нэмэх нь сайжруулах зүйл.
